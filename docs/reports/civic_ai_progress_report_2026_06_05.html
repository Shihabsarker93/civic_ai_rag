1. Executive Summary

We now have a working local Civic.ai RAG prototype for Bangladeshi birth/death registration. The current system is not a generic chatbot: it retrieves indexed government-service evidence, reranks it, and answers with source IDs and official/source links. For high-risk civic questions such as fees, correction, required documents, deadlines, and lost certificates, CivicRAG uses controlled evidence-based answer paths to reduce hallucination.

The project direction has been narrowed from a multi-domain prototype to a clean single active domain first: birth/death registration. Previous passport and BRTA data were removed from the active pipeline so that the current vector database is clean and domain-specific.

The implementation is closest to the NextRAG paper at the architectural level: simple baseline versus proposed advanced pipeline, multiple LLM backends, bilingual/cross-lingual goals, and grounded retrieval. However, the system is not yet at the paper's evaluation maturity because a labeled gold QA set and numeric metrics are still pending.

4. Chunking Strategy

We chose document-type-aware chunking instead of one universal chunk size. This aligns better with government-service data, where FAQs, laws, fee tables, notices, and process guides have different retrieval behavior.

Data typeChunking choiceReason
FAQ JSONOne question-answer pair per chunkKeeps user intent and answer together; strong for exact citizen questions.
Legal act/rulesOne ধারা or বিধি per chunk, split if longPreserves legal authority and section-level citation.
Fee tableFull table chunk + row-level fee chunksSupports broad fee questions and exact amount questions.
Application processHeading/step-based chunksImproves “কীভাবে করব” procedural retrieval.
Correction processScenario/section chunksSeparates parent-name, address, birth-date, and contact scenarios.
Portal/homepage contentOnly citizen-service/support sections retainedRemoves menus, footers, news lists, and portal noise.
Scanned PDF/OCROCR to Markdown, then structured chunksAllows scanned notices/guidelines to be indexed, but with lower confidence metadata.

This is thesis-defensible because it allows ablation: FAQ-only vs legal-only vs process-guide chunks, OCR on/off, row-level fee chunks on/off, and simple fixed-size chunking vs structured document-aware chunking.

5. What Makes CivicRAG “Ours”

The LLMs are not our model. Our contribution is the RAG system: data pipeline, chunking strategy, multilingual retrieval setup, reranking, safe answer generation, citations, and evaluation plan.

Simple RAG baseline

  • Dense vector search only.
  • Less domain-aware reranking.
  • LLM has more freedom to synthesize.
  • Useful as a tutorial/baseline comparison.

CivicRAG / proposed pipeline

  • Hybrid dense + BM25 retrieval.
  • RRF fusion and BGE reranking.
  • Civic intent boosts for fees, correction, documents, lost certificate, and online visibility.
  • Safe evidence-based answer paths for high-risk civic questions.
If all three models give the same answer in CivicRAG, that is not automatically a problem. For high-risk fee/procedure questions, the system intentionally uses controlled grounded answers instead of letting each local LLM freely rewrite the response. This improves factual stability.

9. Recommended Next Steps

  1. Create a gold QA dataset. Start with 50 to 100 Bangla questions across fee, application, correction, legal, FAQ, online visibility, lost certificate, and out-of-context categories.
  2. Label expected source IDs. For retrieval metrics, each question needs one or more relevant source chunk IDs.
  3. Run retrieval metrics. Measure Recall@3, Recall@5, MRR, and nDCG for Simple RAG vs CivicRAG.
  4. Run answer metrics. Use reference answers plus qualitative faithfulness checks; BERTScore or semantic similarity can be supportive, not the only evidence.
  5. Add English and code-mixed tests. This is necessary because the thesis goal is bilingual/cross-lingual Civic.ai, not Bangla-only service search.
  6. Do ablations. Compare dense only, BM25 only, hybrid without reranker, hybrid with reranker, and CivicRAG with safe answer paths.
  7. Review OCR guideline chunks. Keep OCR data marked as lower confidence until manually verified.
  8. Prepare a method diagram. Show the separation between ingestion, cleaning, chunking, embedding, retrieval, reranking, generation, and evaluation.
